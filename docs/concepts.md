# 1단계 개념 정리 (초보 눈높이)

## VM과 컨테이너

- **VM(가상 머신)**: 컴퓨터 안에 가짜 컴퓨터를 통째로 만든 것. CPU·메모리·디스크를 따로 받고, 자기만의 운영체제(커널 포함)를 부팅한다.
  우리 VM 3대는 각각 Ubuntu를 통째로 돌린다. 무겁지만 진짜 서버처럼 완전히 분리된다.
- **컨테이너**: 운영체제(커널)는 호스트와 같이 쓰고, 프로그램과 그 프로그램이 쓰는 파일만 상자에 담아 따로 돌리는 것. 몇 초 만에 뜨고 가볍다.
- 비유: VM은 "아파트 한 채를 따로 짓기", 컨테이너는 "한 집 안에서 방을 나눠 쓰기".
- 이 플랫폼에서는 둘 다 쓴다. VM 3대가 "서버 3대" 역할을 하고, 그 위에서 k3s가 컨테이너(MySQL, Spring 앱 등)를 돌린다.
- 참고: Docker Desktop도 맥에서 리눅스 커널이 필요해서 속에서는 VM 하나를 돌린다. 그래서 메모리를 따로 떼어 가는 것이다.

## IP 주소

- 네트워크에서 기계를 찾는 주소. 예: `192.168.252.5`. 숫자 4개(각 0~255)로 되어 있다 (IPv4).
- 같은 네트워크 안에서는 IP가 겹치면 안 된다.

## 서브넷

- "같은 동네"에 속한 IP 범위. `192.168.252.0/24`라고 쓰면 앞 24비트(`192.168.252`)가 동네 이름이고, 마지막 숫자(0~255)만 집마다 다르다.
- 같은 서브넷 안의 기계끼리는 중간 장치 없이 바로 통신한다. 우리 맥과 VM 3대는 모두 `192.168.252.0/24` 안에 있다.
- `/24`가 클수록(`/28`) 동네가 작고, 작을수록(`/16`) 동네가 크다.

## 게이트웨이

- 동네 밖(다른 서브넷, 인터넷)으로 나가는 출구. VM이 github.com에 접속하면 먼저 게이트웨이로 보낸다.
- Multipass 네트워크에서는 맥이 게이트웨이(`192.168.252.1`)다. VM 안에서 `ip route`를 치면 `default via 192.168.252.1`이 보인다.
  맥 쪽에서는 `ifconfig bridge100`에 이 주소가 붙어 있다. (대역 숫자 252는 맥마다 다를 수 있다. `multipass list`로 확인)

## NAT (주소 변환)

- VM의 `192.168.252.x`는 맥 안에서만 통하는 사설 주소라 인터넷에서는 모른다.
- VM이 밖으로 나갈 때 맥이 보내는 사람 주소를 "맥의 주소"로 바꿔서 대신 보내고, 답장이 오면 다시 VM에게 돌려준다. 이것이 NAT다.
- 공유기가 집 안 기기들을 인터넷에 내보내는 것과 같은 원리다.
- 결과: VM → 인터넷은 되지만, 인터넷(또는 같은 와이파이의 다른 기기) → VM으로는 직접 들어올 수 없다. 맥에서 VM으로는 같은 서브넷이라 된다.

## DHCP와 고정 IP

- **DHCP**: 기계가 네트워크에 붙으면 "IP 주세요" 하고 자동으로 받아오는 방식. Multipass VM은 맥(macOS의 bootpd)에게서 DHCP로 IP를 받는다.
- 받은 IP는 "임대(lease)"라서 원칙적으로 바뀔 수 있다. 보통은 VM의 MAC 주소(네트워크 카드 고유번호)를 기억해서 같은 IP를 다시 주지만, 보장은 아니다.
  기록 위치: 맥의 `/var/db/dhcpd_leases`
- **고정 IP**: 기계에 IP를 직접 정해두는 방식. 서버는 보통 고정 IP를 쓴다.
- 이 저장소의 선택: Multipass(맥)에서 고정 IP를 설정하는 것은 꽤 복잡하고 잘 깨진다. 그래서 DHCP를 그대로 쓰되,
  IP를 직접 쓰는 곳을 `~/.ssh/config.d/platform-infra`와 VM의 `/etc/hosts` 두 곳으로 모으고, `update-hosts.sh` 한 번으로 고칠 수 있게 했다.
  Ansible 인벤토리는 IP 대신 별칭을 써서 고칠 필요가 없다.

## SSH 키 방식

- SSH: 다른 컴퓨터에 원격으로 접속해 명령을 치는 프로그램.
- 비밀번호 대신 **키 한 쌍**을 쓴다.
  - 개인키 `~/.ssh/platform_ed25519`: 맥에만 있고 절대 남에게 주지 않는다 (권한 600 = 나만 읽기).
  - 공개키 `~/.ssh/platform_ed25519.pub`: 자물쇠 같은 것. 서버(VM)의 `~/.ssh/authorized_keys`에 등록해둔다.
- 접속할 때 서버가 "이 자물쇠에 맞는 열쇠를 가졌는지 증명해봐" 하고 문제를 내면, 맥이 개인키로 풀어 보여준다. 개인키 자체는 네트워크로 나가지 않는다.
- 장점: 비밀번호를 훔쳐볼 수 없고, Ansible처럼 자동화 도구가 사람 입력 없이 접속할 수 있다.
- 이 프로젝트 전용 키를 따로 만든 이유: 다른 곳(GitHub 등)에 쓰는 키와 섞이지 않게, 그리고 VM을 다 지우면 키도 같이 정리하기 쉽게.
- 개인키에 암호(passphrase)를 걸지 않은 이유: 학습용 로컬 VM이고 Ansible 자동화를 단순하게 하기 위해서다. 실제 회사 서버라면 암호를 걸고 ssh-agent를 쓴다.
- **호스트 키**: 반대로 맥도 "내가 접속한 게 진짜 cp1이 맞나?"를 확인한다. 처음 접속할 때 VM의 호스트 키를 `~/.ssh/known_hosts_platform`에 기억해두고, 다음부터 달라지면 경고한다.

## cloud-init

- VM이 **처음 켜질 때 딱 한 번** 실행되는 초기 설정 도구. 클라우드(AWS, GCP 등)의 거의 모든 리눅스 이미지에 들어 있는 업계 표준이다.
- `multipass/cloud-init.yaml`에 "이 공개키 등록, 이 패키지 설치, 시간대는 서울" 같은 원하는 상태를 적어두면, VM이 부팅하며 알아서 해준다.
- 손으로 VM에 들어가서 하나씩 설정하지 않으므로 VM을 지우고 다시 만들어도 똑같은 상태가 된다.
- 한계: 처음 한 번만 실행된다. 이미 만들어진 VM의 설정을 바꾸는 것은 Ansible이 맡는다.

## Ansible

- 여러 서버에 같은 작업을 시키는 자동화 도구. 맥에서 실행하면 ssh로 VM에 들어가 작업한다.
- VM에 따로 설치할 프로그램(에이전트)이 없다. ssh와 파이썬만 있으면 된다 (그래서 cloud-init에서 python3를 넣었다).
- **인벤토리**(`ansible/inventory.ini`): 관리할 서버 목록과 그룹. `control_plane`, `workers` 그룹으로 나눠두면 "워커에만 이 작업" 같은 지시가 쉬워진다.
- **모듈**: Ansible이 할 수 있는 작업 단위. `ping`(연결 확인), `apt`(패키지 설치), `copy`(파일 복사) 등.
  `ansible all -m ping`은 "인벤토리의 모든 서버에 ping 모듈을 실행"이라는 뜻이다. 네트워크 ping이 아니라 ssh 접속 + 파이썬 실행까지 되는지 확인한다.
- **플레이북**: 여러 작업을 순서대로 적은 YAML 파일. 2단계에서 k3s 설치를 플레이북으로 만든다.

### 셸 스크립트와 무엇이 다른가

- **멱등성(idempotency)**: 몇 번을 실행해도 결과가 같다. Ansible의 `apt: name=curl state=present`는 "curl이 설치된 상태여야 한다"는 뜻이라, 이미 있으면 아무것도 안 하고 `ok`, 없을 때만 설치하고 `changed`를 보여준다.
  셸 스크립트로 같은 걸 하려면 `if ! command -v curl ...` 같은 확인을 매번 직접 짜야 하고, 빠뜨리면 두 번째 실행에서 깨진다.
- **원하는 상태를 적는다(선언형)**: 셸은 "이렇게 해라"(명령), Ansible은 "이렇게 되어 있어야 한다"(상태)를 적는다.
- **여러 서버에 동시에**: 셸이면 `for host in ...; do ssh ...` 루프를 짜야 하지만 Ansible은 그룹을 지정하면 병렬로 실행하고 서버별 결과를 정리해준다.
- **미리 보기**: `--check --diff`로 실제로 바꾸지 않고 무엇이 바뀔지 볼 수 있다.
- 그래서 이 저장소는 "VM 만들기"처럼 맥에서 한 번 돌리는 일은 셸 스크립트로, "VM 안의 설정"은 Ansible로 나눈다.
